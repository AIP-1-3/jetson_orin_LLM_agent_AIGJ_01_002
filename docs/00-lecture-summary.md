# EmbeddingGemma 2 실습 자료 정리와 2호기 준비

자료: "Jetson 실습 - EmbeddingGemma 2 멀티모달 임베딩" (2026-10-08 작성, 10단계 + Q&A 14개)
정리일: 2026-10-23

## 1. 한눈에 보기

- 이 자료는 **LLM 에이전트 자체가 아니라 임베딩 모델(EmbeddingGemma 2) 실습**입니다. 텍스트·이미지·동영상·음성을 같은 768차원 벡터 공간에 넣고 서로 검색하는 법, 그리고 그걸 카메라 응용(물체 검색, 동작 인식, 접근 감지)으로 넓히는 내용이에요.
- "에이전트"는 두 군데에서만 나옵니다. 7단계 학습 데이터 주제("에이전트 권한" 등)와 10단계 끝의 "알람을 MQTT로 내보내면 환경 모니터링 에이전트·팀 프로젝트와 연결된다"는 문장이에요. 즉 **에이전트가 쓸 검색(RAG)·감지 부품**을 만드는 자료로 보입니다.
- **제출물·마감·평가 항목은 자료에 적혀 있지 않습니다.** 대신 단계마다 직접 채우는 빈 결과표와 "확장 과제"가 있어서, 이 표들이 사실상 결과물 뼈대예요.

## 2. 단계별 핵심

| 단계 | 하는 일 | 채울 결과표 / 과제 |
| --- | --- | --- |
| 1 환경 | SSD·스왑·전력 모드, JetPack에 맞는 GPU용 PyTorch | GPU 커널 실행 확인 (`(8, 7) True` + 숫자) |
| 2 설치 | torch 버전 고정 후 sentence-transformers 6.1+ 설치, 모델 받기(1.5~3GB), 공통 로더 `eg2.py` | `(768,)` 출력 |
| 3 텍스트 | 질의/문서 프롬프트 구분, 768/256/128차원 비교 | 변형: `prompt_name` 빼고 점수 비교 |
| 4 영상 | 이미지·동영상 임베딩, 텍스트로 이미지 찾기 (동영상은 RTSP에서 10초 녹화) | 확장: 텍스트+이미지 혼합 입력 |
| 5 음성 | 16kHz 모노 변환, 텍스트로 소리 찾기 | 건너뛰어도 되는 단계 |
| 6 성능 | 구성별(270M/440M/570M/740M) RAM·지연·GPU 사용률 | **자원 사용량 표** (tegrastats) |
| 7 미세 조정 | 강의실 도메인 질의-문서 282쌍으로 텍스트 모델 학습 | **학습 전/후 Recall·nDCG 표** (평가 60쌍) |
| 8 웹캠 물체 검색 | YOLO → 크롭 임베딩 → FastAPI 웹 검색. COCO 밖 물체 오인식을 재라벨·YOLOE로 개선 | **8-4 라벨 비교표 + fps·ms·RAM 표** |
| 9 동작 인식 | 관절 17개로 만세·손 흔들기·악수, 시간 안정화, 관심도, GRU 학습 | **9-4 비교표**, 낯선 사람으로 평가 |
| 10 접근 감지 | USB 카메라 2대 보정 → 삼각측량 → 접근 알람, 칼만 필터 | **10-7 거리 오차표**, 확장: MQTT 연동 |

자료가 권하는 최소 경로: 1 → 2 → 3 → 4 → 6, 그다음 텍스트 RAG면 7, 카메라 응용이면 8 → 9 → 10.
8단계부터는 모두 **문제 확인 → 개선 → 결과 비교** 순서라서, 그대로 따라 하면 AI 채점 가이드의 "실패 → 원인 → 해결"과 "전/후 실측 표"가 자연스럽게 채워집니다.

## 3. 자료와 우리 장비가 다른 점 (2호기 기준 주의)

| 자료 내용 | 우리 상황 | 할 일 |
| --- | --- | --- |
| JetPack 6 / CUDA 12.6 기준으로 쓰임 | 1호기는 JetPack 7.2.1 (L4T R39, Python 3.12, CUDA 13.2). 2호기도 같은 이미지라면 동일 | 표의 **JetPack 7 경로**(`cu132` 인덱스)를 씁니다. R39도 JetPack 7이에요 |
| torchaudio 설치 | JetPack 7에서는 CUDA 버전이 어긋나 sentence-transformers 전체가 막힘 (자료 Q7) | torchaudio는 처음부터 설치하지 않고 soundfile·librosa로 음성 처리 |
| 0번 SSD 파티션·포맷 명령 | 1호기는 NVMe로 부팅 중 | `lsblk`에서 `nvme0n1`이 `/`이면 **절대 실행하지 않음** (디스크 전체 삭제) |
| 스왑 8GB 추가 | 1호기는 `/swapfile` 8G가 이미 있음 | `free -h`로 스왑이 이미 있으면 생략 (중복 등록 방지) |
| `nvpmodel -m 0` | MAXN_SUPER 번호가 장비마다 다름 (1호기는 2번) | `sudo nvpmodel -q`로 확인 후 번호 지정. 2호기는 단독 사용이라 팀 합의 대상 아님 |
| 8·9단계 USB 웹캠 (`cv2.VideoCapture(번호, CAP_V4L2)`) | 2호기는 **IP 카메라 TP-Link VIGI** (RTSP) | 카메라 입력 한 줄을 RTSP 주소 + `cv2.CAP_FFMPEG`로 바꾸고, 지연이 쌓이지 않게 최신 프레임만 남기는 구조 확인 |
| 10단계 USB 카메라 2대 + 체커보드 보정 | 2호기는 IP 카메라 1대 | 2호기 VIGI IP 카메라 1대 + 1호기 팀원의 USB 카메라 1대를 함께 써서 2대 구성으로 진행 (2026-10-23 민서 확인). 두 카메라가 다른 장비·다른 망에 있으므로 프레임 시각 맞추기와 한쪽으로 영상을 모으는 경로를 먼저 정해야 함 |
| 메모리 | 8GB를 CPU·GPU가 공유 | YOLO + EmbeddingGemma 동시 실행 전 6단계 표로 여유 확인. 무거운 작업은 `tmux` 안에서 |

RTSP 주소·카메라 계정은 코드나 git에 적지 말고 환경변수로 넘깁니다 (예: `export CAM_URL=...` 를 `~/.bashrc`가 아닌 별도 파일에 두고 `source`). VIGI의 정확한 스트림 경로(보통 메인/서브 스트림 두 개)는 VIGI 앱이나 카메라 웹 설정에서 확인해 주세요.

## 4. 2호기 준비 순서 제안

1. **기본 세팅 먼저** ("Jetson 2호기 세팅" 스레드): SSH, Tailscale, 계정. 이게 끝나야 원격으로 같이 진행할 수 있어요.
2. **버전 확인** (2호기 터미널에서, 한 줄씩):
   ```bash
   cat /etc/nv_tegra_release
   ```
   ```bash
   lsb_release -rs
   ```
   ```bash
   python3 -V
   ```
   ```bash
   lsblk
   ```
   ```bash
   free -h
   ```
   결과로 JetPack 6/7, NVMe 부팅 여부, 스왑 유무를 판단합니다.
3. **실습용 venv와 GPU용 PyTorch** (`~/eg2`, `cu132` 인덱스) → 커널 실행 검증까지.
4. **torch 버전 고정 후 sentence-transformers 설치, 모델 미리 받기** (약 3GB, 수업 중 다운로드 대기 방지). Hugging Face 캐시는 NVMe에 둡니다.
5. **VIGI 카메라 연결 확인**: 2호기와 카메라가 같은 네트워크에 있는지, RTSP로 10초 녹화가 되는지 (`ffmpeg -rtsp_transport tcp ...`, 4단계 명령).
6. **측정 습관 만들기**: 매 실습마다 `tegrastats` 로그를 파일로 남기고 전력 모드·정밀도(bfloat16)·입력 크기를 함께 적기. 6·7·8단계 표가 그대로 보고서 근거가 됩니다.


## 5. 결과물로 남길 것 (AI 채점 가이드 기준)

- 6단계 자원표, 7단계 학습 전/후 Recall·nDCG, 8-4 라벨·속도 비교표를 **같은 조건(전력 모드, bfloat16, 해상도)**으로 채우고 tegrastats 로그를 근거로 둡니다.
- Q&A처럼 실제로 겪은 오류는 "증상(에러 메시지) → 원인 → 해결 → 재발 방지"로 기록합니다. JetPack 7 차이 때문에 자료와 다르게 한 부분이 좋은 사례가 됩니다.
- 사람 이미지는 저장하지 않는다는 자료의 원칙(8·9·10단계)을 그대로 지키고 문서에도 적습니다.
